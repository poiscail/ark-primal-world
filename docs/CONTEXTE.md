## Pièges connus
- `T3` et `alive` sont des `const` : inaccessibles via `window.T3` ; utiliser `S.team.slice(0,3)`.
- `SK_of` est `const` (compétence lue sur `SPEC[type].sk`).
- `renderBattle` est réassigné par ~15 modules ; l'ordre compte. `stageBuild()` est appelé depuis 94-battle-anim juste après le rendu de base ; les modules ultérieurs cherchent `.sHud`/`.sFig` (avec repli sur l'ancien `.panel`).
- `giveXP`/`give()` : `give` gère matériaux (`S.mat`) ou champs de `S` (tickets, shards…).
- Comparer deux états après transfert : appeler `ens()` avant (champs par défaut ajoutés).
- Tester les boutons par de **vrais clics** Playwright (pas seulement en appelant la fonction) : une couche d'effets peut intercepter les clics (bug du bouton OK d'invocation, corrigé dans les deux branches).
- Sous-onglets (99-nav) : un bouton d'un autre sous-onglet est caché (`.subhide`) ; dans un test, ouvrir d'abord son sous-onglet (clic sur `#subnav button[onclick="subSet('summon','bonus')"]`, voir `show()` dans `test_summon_buttons.py`).
- Fenêtre minimale de l'application : 1024×640 (`desktop/main.js`) ; les orbes, la super et les compétences doivent y rester visibles sans défiler (règle compacte `max-height:760px` dans `94-layout.css` ; les boutons secondaires du bas — Aide, Garde, Fuir, Journal — passent sous la ligne de flottaison, même à 1280×800). `test_layout.py` vérifie 1280×800, 1366×700 et 1920×1080.
- Éviter les `sleep` enchaînés pour attendre des tests ; utiliser un `until` avec timeout.
- Combat : ne jamais déplacer les nœuds de `#battleArea` ; `99-layout.js` (dernier script) les étiquette `bl-*` et `css/94-layout.css` règle l'ordre (grille 2 colonnes). Un nouvel élément non reconnu par `blKind()` va en fin d'écran.
- Animations de combat : délais via `fxd(ms)` (vitesse `FX_SPEED`, `let` dans 94), effets dans `#fxLayer` via `fxAdd`. Une compétence n'anime que son lanceur (`BQ.sk` → `castFx`) ; orbes/super → `atkFx` par famille (`PORT[type][0]`) ; riposte ennemie jouée après 480 ms (`foeFx`).
- `eye()` (portraits) est remplacé temporairement pendant `corruptSVG` (yeux luisants) : les portraits du joueur restent identiques (testé).
- Noms et variété des ennemis appliqués à l'affichage (`bnName`/`cxVary` dans `stageBuild`), car `startBattle` peut être différé par un dialogue d'histoire (dans l'application, `navigator.webdriver` est faux : couper `lore` pour un test automatique).
- Trait « Carapace » (dès le niveau 8, aléatoire) : un coup peut être absorbé à 0 → dans les tests de dégâts, niveau < 8 ou `e.tr="";e.sh=0`.
- Tests d'effets : compter les ajouts au `#fxLayer` (MutationObserver) plutôt que le nombre net d'enfants (les effets précédents disparaissent en même temps).
- Coupure de super attaque : `special()` est différé de ~1,25 s (÷ vitesse) quand les animations sont actives ; désactivée sous `navigator.webdriver` sauf `window.__forceCutin` (comme les dialogues) ; dans l'application (Electron) elle est active. Pendant la coupure, `tapOrb`/`useSkill` ne font rien.
- Secousse et parallaxe utilisent les propriétés CSS `translate`/`rotate` (indépendantes de `transform`) : ne pas poser d'autre `translate` sur `.battlestage`, `.sc-layer`, `.sTeam`, `.sEnemy`, `.heroDino`. Le gel `hitStop()` ne met en pause que les animations « running » de `#battleArea`/`#fxLayer` (relancer une animation terminée la rejouerait).
- Mise en page PC : la navigation `.bottomnav` est une colonne fixe à gauche (`--rail`) ; pour « le bas de l'écran » dans un test, prendre `innerHeight` si la barre est verticale (voir `test_layout.py`).
- Chef/liens : bonus appliqués au premier rendu du combat (`tmApply` dans le wrapper de `renderBattle`), car `startBattle` peut être différé (dialogue) et les modes (80-modes) créent d'abord un combat d'histoire puis le transforment (`f.o`, `f.zone`, `f.enemies` changent ensuite) : tout ce qui dépend du mode doit être calculé paresseusement (voir `wxOf`).
- Labyrinthe : PV de course = rapport par place (`S.maze.run.hp`), enregistré à chaque rendu d'un combat du labyrinthe (`f.mzOn`) et appliqué par `mzSetup` après `tmApply` (chef/liens). Combat via `MODES.maze`, victoire via `eventWin` remplacé, défaite via `settleLose` remplacé. Relancer la même case reprend le combat en cours (même `key`) : dans un test, `fight=null` avant `mzFight()` pour un nouveau combat. Les combats normaux commencent à la vague 2 (`f.mzW0=1`, 2 ennemis) : titre et bannières renumérotés. Niveau des ennemis : `mzN0()` = progression d'histoire ou 2×(niveau moyen de l'équipe − 1) si plus haut.
- Objets : lire l'attribut d'un objet avec `paOf(it.pa)` (70-equipment), jamais `PA[it.pa].i` : au chargement, la sacoche et le sac s'affichent avant que `99-species2` déclare ses attributs (erreur réelle trouvée par test_nightmare, 0.24).
- Nouvelles compétences (0.24) : le moteur de base (switch de `useSkill`) ne les connaît pas ; `99-species2` calcule l'effet avant d'appeler `useSkill`, pose `f._skx={dmg,msg}` que son wrapper d'`afterAction` ajoute aux dégâts (avant les carapaces de `99-enemy-traits`). Ce module doit rester avant `99-trials` (« sans compétences » prioritaire). Durées (`f.ewk`, `f.taunt`, `f.rly`) décomptées dans son wrapper d'`enemyTurn` ; `f._bigNow` signale une attaque puissante pendant ce tour (Écailles épaisses).
- Épreuves : un combat d'épreuve est refusé si l'équipe n'est pas conforme (`trTeamOk`) ; « Former l'équipe » réordonne `S.team` et mémorise l'ancienne tête (`S.trial.prev`). Règles : `nosuper` (jauge remise à 0 à chaque rendu, sinon l'auto-combat appellerait `special()` en boucle), `noskill` (recharges à 99), `timed` (`f.trAct` compte orbes + super, défaite via `settleLose`).
